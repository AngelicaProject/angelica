# In-game interface

## Overlay

The host draws its interface over the game with **egui** and its own Direct3D 11 painter. It hooks the swap chain's `Present` and resizing through the swap chain's vtable, obtained from Direct3D 11 itself, and receives input through a window procedure hook. Neither depends on the game map, so the overlay works on a build the map does not cover and can always report what is disabled and why.

The overlay chains with other tools that draw over the game; it does not assume it is the only `Present` hook. It draws only into a swap chain whose window the game's startup thread made, the thread the host starts on and the game creates its window on; a swap chain another tool presents to a window of its own is passed on untouched.

The bootstrap swap chain that finds `Present` is made on the software rasterizer (WARP), never on the graphics adapter, and released with its window once `Present` is hooked; DXGI, which holds the vtable and its functions, is pinned in the process instead. One kept on a GeForce RTX 3060 after its window was destroyed made the game's device fail with a graphics exception after some seconds. Its vtable is DXGI's and the same as the game's swap chain's. Bootstrap device creation requests the swap chain, device, feature level, and immediate context together. Graphics interposers can interpret a missing device output as a capability probe and omit swap-chain creation. Incomplete outputs fail initialization and release the bootstrap window; the host log distinguishes installed hooks from attachment to a rendering swap chain.

The menu key, `Insert` unless the player chose another, opens and closes the Angelica menu, and so do `/angelica` in the game's chat, with any words after it, and **Angelica** at the top of the game's System menu, after the game's boxed letter A. The host takes the line from the game's command handler (the same detour as plugins' [commands](../formats/plugin-api-v1.md#commands)) and the System menu's entry from the menu itself ([game structures](../formats/game-structures.md#system-menu)), both installed at start while the overlay draws, and the game does not run the line or the entry; `Esc` and the close button in its title bar close it, and the game starts with it closed. The game does not receive the menu key. Plugin windows are shown whether the menu is open or closed. In text fields, Ctrl+V pastes text from the Windows clipboard and Ctrl+C and Ctrl+X copy and cut to it. Mouse messages are consumed only while egui requests them. Keyboard messages reach Angelica's windows and are consumed only while a text field has focus — a pressed button or a chosen row does not take the keyboard — so the player moves and types in the game with the menu open, and a key never moves the focus between Angelica's controls. A key's or a mouse button's release always reaches the game, so one the game saw pressed never stays pressed for it, as when the camera turns with a button held and the pointer ends over Angelica's window; the one exception is `Esc` while the menu is open, which closes the menu and does not reach the game. System keys such as Alt+F4 always reach the game while the menu is open. A disabled overlay releases capture. The overlay draws into the game's back buffer on the game's immediate context during `Present`, skipping presents with `DXGI_PRESENT_TEST`: it saves every part of the context's state it sets (render targets, viewports, scissor rectangles, rasterizer, blend, and depth-stencil states, input layout, topology, vertex and index buffers, the vertex, hull, domain, geometry, and pixel shaders with their class instances, the first constant buffers, shader resource, and sampler) and puts it back after drawing. A frame's vertices and indices go into one dynamic vertex buffer and one dynamic index buffer that are made once and grow, not into new buffers every frame. When it attaches, it logs the graphics adapter, its driver, the device, and the game's swap chain; a device that stops is logged with its reason and whether it stopped before Angelica drew a frame. A frame with nothing to draw does not touch the back buffer or the context. The render target view on the back buffer is made once for that buffer and kept between frames, as proven overlays do, instead of being made again every frame; only a resize of the game's own swap chain drops it, before forwarding to the original function, and the interface keeps its windows, tabs, and text. A new swap chain of the game's window gets a new painter, with the interface kept. A partial update of a texture, as when new letters enter the font atlas, is written into the texture in place.

When rendering runs outside the startup thread, a registered Windows message schedules ticks and UI events on the window thread. Main callbacks run only if it matches the startup thread. The renderer uses cached window descriptions. A mismatch disables the overlay with a diagnostic.

## What the host shows

Angelica's interface is a small window over the game, the size of the game's own windows, and follows the same principles: a title bar, tabs, a dense list, actions in the row and in the right-click menu, details under the chosen row, and short actions at the bottom. It does not copy the game's look and does not dim the game. The window can be moved, and keeps its place while the game runs.

The face of Angelica uses plain words; ids, paths, permission names, logs, and technical errors appear only under **For developers**.

Every window of Angelica and of plugins has the same title bar, and each of its parts has one role. On the left is where the player is: the word `angelica` in lowercase, small and in a muted color, in the menu only; a dialog's title; or a plugin window's title, followed, when the plugin gives one, by the path below the window's top level with a back arrow, where the title and each earlier part lead back. Before the controls is what goes on: one short line with a mark, a dot in the "on" color or the attention mark. On the right edge are the window's controls. A long path is cut first and keeps at most six tenths of the room when there is a status; a status that does not fit is cut with an ellipsis and shown whole under the pointer; the controls always stay.

The menu's bar shows how many plugins wait for the player and how many run, a menu button (**Arrange panels**, **Check for updates**, **Settings**, **For developers**), and the close button. A dialog's bar has its title and the close button. Below the menu's bar are the tabs **Installed**, **Catalog** ([catalog](./catalog.md#in-the-game)), and **Settings**; all three keep the same height. The player moves the menu by its bar and resizes it from any edge or corner as a plugin window, from its normal 640 points wide and four lines of the list tall; where it is and its size are kept across game starts ([layout](../formats/host-installation-v1.md#layout)).

**Installed** has a search field that filters by name and description. The list is grouped under small section headers with a count and a thin rule: needs attention (awaiting approval, also when a new version asks for more, or stopped after a failure), on, and off, each sorted by name. The list scrolls; with fewer plugins it keeps the height of seven rows, and Settings have the same height as Installed, so the window keeps its size. A row is 50 points high and shows, always and without the pointer:

- the plugin's icon ([plugin file](../formats/plugin-file-v1.md#layout)), or a square tile with rounded corners holding the first letter of its name;
- the name, and under it the description, or, in the attention color, what the plugin waits for: the player's permission, the player's decision on a new version that asks for more, or a retry after a failure. An off plugin's name and tile are muted;
- at the right, for a plugin that waits for the player, the action as a word: **Allow…** for one awaiting approval, and **Try again** for one stopped after a failure;
- a switch: a small track in the "on" color with its knob at the right while the plugin runs, a pale track with the knob at the left otherwise. It turns the plugin on or off; for a plugin awaiting approval it opens the plugin's page;
- a `⋯` button with the plugin's menu.

Clicking a row opens it, and clicking it again closes it; the open row is highlighted and shows under it, for a plugin stopped after a failure, its description, why it stopped, and **Copy report for the author**; the version, the authors, and where the plugin comes from; and a line with **Plugin management →** on the left for a running plugin, which sends the plugin `open-requested` and brings its windows in front of the menu, which stays open, and **About plugin** on the right, which opens the plugin's page. A double click on a running plugin's row does what **Plugin management** does. Clicking a plugin awaiting approval opens its page at once. The `⋯` button and a right click open the same menu, headed by the plugin's tile, name, and state, the tile where the items' words begin: **About plugin…** first, in the action color, then **Copy report for the author**, **Open plugin folder** for all but a plugin awaiting approval, and **Remove…**.

**About plugin** is a page of the menu under the tabs, none of them chosen, in place of their content and in its height; the bar reads `angelica › <plugin>` with a back arrow. Any tab, the back arrow, or `Esc` leads back; `Esc` closes the menu only from a tab. Its head has the plugin's tile, name, version, its authors, and where it comes from (the Angelica catalog, or in development on this computer), and for a plugin that does not wait, its switch, with **Plugin management** for a running one and **Try again** for one stopped after a failure. Under it are a plate saying that the plugin was just turned on, or why it stopped; the description; what the plugin may do, under the name of each permission class, the most serious first, in plain words with the sites a network or link permission reaches; what the plugin installer did with it in this game session (installed, updated from one version to another, compiled again, or failed); and in the last line **Copy report for the author**, **Open plugin folder**, and **Remove…**.

For a plugin awaiting approval the page asks: its title is **Turn on <plugin>?**, and it shows what the plugin would be able to do in the same form, with the warning that acting for the player in the game breaks the game's terms of service under a permission of that class. For a new version of an approved plugin the title is **<plugin> asks for more**, the line under it says that it does not run until the player decides, and the page shows only what it asks for the first time, then in one line the classes already allowed. Its actions are **Allow and turn on** (**Allow the new** for a new version) and **Not now**, which leaves the plugin waiting and goes back to the list. A permission is granted only there.

**Copy report for the author** puts on the clipboard what the player sends a plugin's author when something goes wrong, written by Angelica in English: Angelica's version, the game build, the map's state, the plugin's name, id, version, and origin, its state with the reason it stopped, its permissions, what the plugin installer did with it in this session, and the last lines of its log. A plugin tells about its work through its log; it has no report of its own, and it never reads the clipboard: with `clipboard.write` it only puts text there while handling the player's click or command ([plugin API](../formats/plugin-api-v1.md#clipboard)). After the copy the action reads **Report copied**.

**Remove…** opens a dialog with the plugin's tile, name, and version and two ways to remove it: keeping its data (its storage folder, which a plugin with the same id finds again when installed later) or with its data. Removing stops the plugin and takes it out of the list at once ([lifecycle](./plugins.md#lifecycle)).

Below the list, a field takes an `https` link to a [plugin file](../formats/plugin-file-v1.md). Once a plugin from a link or the catalog is installed, the menu shows its page with the question, at once if the menu is open and the next time it opens otherwise.

**Settings** has a column of sections on the left, each with a small icon, on a background slightly darker than the window; the chosen section is a light rounded plate inset in that column and does not merge with the right side. The sections are:

- **General**: the key that opens Angelica and the key that stops plugins acting, each shown as a small key token; the language; the theme; the interface size, which scales all of Angelica on the screen (the menu, plugins' windows, panels, popups, and notes): small, normal, or large. The size grows with the square root of the screen's height, so a high resolution makes the interface only a little larger. A click on a key token asks for another key, and the next key pressed becomes that key when it is `Insert`, `Delete`, `Home`, `End`, `Page Up`, `Page Down`, `Pause`, `Scroll Lock`, or `F1` to `F12` and not the other key; `Esc` keeps the current key, and other keys are waited out. The new key applies at once;
- **Updates**: Angelica's version and its last check, the game map's, the channel, and **Check now** for plugins with when they were last checked in this session; plugin updates install automatically, and a version that needs new permissions waits for the player. Every note wraps within the window, and the section scrolls;
- **For developers**: **Dev mode**, **On** or **Off** ([dev mode](../formats/host-installation-v1.md#dev-mode)); the game map for the running build (whether a build record verified it, whether it is the local map of dev mode, and every absent entry with the reason), each plugin with its id, version, state, folder, and recent log, what the plugin installer reported, and recent host diagnostics.

A setting is a row with its name on the left and its value on the right. Choices are short words, one word each where possible.

Enabling, disabling, approving, and retrying apply in the current session, on the main thread at the next frame.

Plugins' marks over the game world are drawn under every window, menu open or closed, projected through the game camera every frame. While the menu is closed, nothing of Angelica is drawn except plugin windows, their marks, and short notes. A note is one line on a small plate at the top right: `angelica`, a mark, and the text; Angelica's own notes end with ` · ` and the key that opens Angelica. The text is how many plugins wait for the player and how many run, for the first seconds of the game and as long as a plugin needs the player; or what the plugin installer did (a plugin installed, a plugin updated with or without new permissions, or a link that could not be installed), for a few seconds. While a plugin acts in the game for the player, and for 3 seconds after, a note names it and the key that stops plugins acting; while plugins are stopped, a note says so and which key lets them act again. While dev mode is on, a note says **Dev mode is on**, with **local map** when a local map is in use. A plugin's notification is a note too, with the plugin's name in place of `angelica`, a mark, and its line, for 7 seconds, after Angelica's own notes; at most 3 are shown, and with attention the game's button on the taskbar flashes while the game is in the background ([plugin API](../formats/plugin-api-v1.md#notifications)). For acting, a note names the stop key in place of the menu key; no note takes input. The game does not receive the stop key.

## Language

Angelica's own interface is in English and Russian. Without the player's choice, it follows the language of the Windows interface: Russian for Russian, English otherwise. The player's choices of language, theme, size, and menu key in Settings are kept in the installation's [state folder](../formats/host-installation-v1.md#angelica-settings). Plugins' windows show what plugins write.

## Look

Angelica's look applies to the menu and to plugin windows alike; plugin authors do nothing for it. There are two themes, light and dark; the player chooses in Settings, and the light theme is the default. Each theme is a fixed set of colors:

| Role | Light | Dark |
|---|---|---|
| Window, 96–97% opaque | `#F6F3ED` | `#1E1B19` |
| Section column in Settings, track of tabs | `#7A5C2E` at 8% over the window | `#181614` |
| Chosen item | white at 75% | `#2E2A26` |
| Text | `#24211C` | `#ECE6DC` |
| Secondary text | text at 60% | `#A8A094` |
| Muted text | text at 42% | `#80796F` |
| Lines and borders | `#3C2D14` at 12–22% | `#ECE6DC` at 8–13% |
| Action words, focus | `#7A5C2E` | `#E8735A` |
| Needs attention | `#B76E00` | `#E0A84E` |
| On | `#2E7D46` | `#7CC48E` |
| Danger | `#B23A3A` | `#EF8FA8` |

Color carries meaning only: the action color for what can be pressed or changed, and the attention, on, and danger colors for states. Everything else uses the text and line colors. There are no gradients or glows.

Motion shows that something changed, and nothing else; the host makes it, the same for Angelica's own windows and for plugins:

| What changes | Motion |
|---|---|
| A window or a panel opens or closes | fades in or out while rising 6 points, 140 ms |
| A window's height follows its content | eases to the new height, 180 ms |
| A tab, or a path in the title bar, changes | the content cross-fades, 120 ms |
| A row appears in a list | slides in from 4 points above, 220 ms |
| A row's mark becomes attention, or a countdown runs out | the row is tinted in the attention color, fading out over 1.4 s |
| A meter or a ring gets a new value | moves to it, 350 ms |
| A readout's number changes | the change shows beside it, then fades, 1.4 s |
| Something runs (the "on" dot) | the dot breathes slowly, 2.6 s |
| A note is shown | it fades in, 250 ms, stays still, and its attention dot blinks, 1.6 s |
| The pointer enters a row or an action | the highlight fades in, 120 ms; an action's underline grows from its middle, 120 ms |
| An action is pressed | it sinks 1 point and dims while held |
| A window is dragged | it lifts: its shadow grows and deepens, 120 ms, and settles when let go |
| A dragged window snaps to an edge | the guide along the shared edge flashes, 300 ms, stays while the window holds the edge, and fades when it is let go, 250 ms |

Nothing else moves on its own: no other looping decoration, nothing tied to scrolling.

Controls are words, not boxes. The main action of a window is a bold word in the action color followed by an arrow (**Allow and turn on →**); secondary actions are words in the secondary text color; an action in a list row is a word in the action color (**+ Install**). A choice is a row of short words with the chosen one in bold text color and the others muted. Tabs are their words on a track in the color of the section column, with the chosen tab on a plate in the chosen item's color, its word in medium weight. A list of values is the current value in the action color with a small chevron. A key is a small token in the action color with a thin border. Text fields keep a plain field with a thin border. Plugin windows are drawn with the same controls: a plugin's window has Angelica's frame and title bar, a heading is a small header with a thin rule, a button is an action word of its kind (main, normal, quiet, or danger), a fact is a name in the secondary color and its value, an entry is a row like the rows of the menu's list — tile (or none in a plain row, whose note goes under the title), title, note, value, mark, actions always shown at the right, and the chosen row's facts and actions under it — a checkbox is its label with the choice of **On** and **Off**, or of the plugin's own two words, and like a choice under other parts it is a setting row with its value at the right edge, its hint under it, and a thin line between settings, a split is a column of sections at the side of the window like the one in Settings, a choice is its current value with a chevron and a menu, tabs are the menu's tabs, and progress is a thin line that fills with the action color. Number fields and sliders keep egui's widgets in the theme's colors.

Windows have 6-pixel corners, a 1-pixel border, and a soft shadow. A title bar is 32 pixels high, list rows 36 pixels, and section headers are small text in the secondary color with a thin rule. Three fonts have three roles: Golos Text for everything the player reads and presses, Quicksand for the word `angelica`, and JetBrains Mono for ids, paths, and logs under **For developers**.

## Places and parts

Plugins do not draw. A plugin builds what it shows from **parts** and puts them in **places** ([plugin API](../formats/plugin-api-v1.md#places-and-parts)); the host lays them out and draws them in Angelica's look, and makes their motion, so the renderer can change without affecting plugins. There are no parts made for one kind of plugin: the same parts make an HP gauge, recast timers, or a checklist, and the set grows with new parts over time.

The host owns fonts, scaling, colors, and frames. The host bundles its fonts for Latin and Cyrillic ([dependencies](../development/dependencies.md#fonts)); after them, the Windows adapter uses the installed Segoe UI font and the first available Meiryo, MS Gothic, or Yu Gothic font for Japanese.

**Places:**

- A **window** is a tool the player opens and closes: Angelica's frame and title bar, scrolling when its content does not fit.
- A **panel** is a small part of the screen the player keeps in view while playing: no frame or title bar, on a plate of the window's color or bare over the game with a shadow that keeps it readable, sized by its parts: about as wide as a party list (never more than a third of the screen) and up to a third of the screen tall. The player places it; clicks pass to the game except on a part that takes them, such as a button or an entry. A plugin says when the panel is shown (always, in combat, out of combat); the player can choose otherwise or hide it.
- A **popup** says something for 2–10 seconds: in the corner with Angelica's notes, large above the middle of the screen, or beside one of the plugin's panels. It takes no input.
- A **dialog** is a question a window asks: drawn over the window, which waits dimmed and takes no input until the player answers with one of the dialog's buttons or closes it.
- **Marks** over the game world ([drawing](../formats/plugin-api-v1.md#drawing-over-the-world)).
- A **menu entry** is a line in one of the game's own menus, such as the menu an item opens: the game draws the menu, and the host adds the plugin's words after the game's own entries, in the color of plugin names. Choosing it tells the plugin what the menu was opened for.

**Parts** are the same in every place: layout (a row, a column, a grid, a spacer, a section, a table, tabs, and in a window a split: sections at its side), text in a role (body, title, value, big, label, small) and a tone, a tile and the game's icons, a meter (a bar or segments), a ring, a readout that shows by how much its number changed, a countdown the host counts down itself, a sparkline, facts, list entries, action words, checkboxes, text fields, choices, and numbers. A part looks the same in a window and on a plate; bare over the game, text is white with a shadow, and meters and rings are white on a dark track.

### Windows

A window's title bar shows the window's title, its path and status when the plugin gives them, and three controls the host draws for every plugin: collapse, a menu (**Open folder**, **Turn off**), and close. A new window is 360 points wide and as tall as its content, up to seven tenths of the screen's height; it opens in the middle of the screen, each next one a step lower and to the right. Its height follows its content until the player resizes it; then it keeps the player's size and what does not fit scrolls. The player resizes it from any edge or corner, at least 240 by 80 points; content wider than the window scrolls sideways: each edge can be taken in a band 6 points outside the frame and 4 points inside it, the edge under the pointer is drawn in the action color, and the pointer becomes the system's resize cursor. Over Angelica's windows the pointer is the system's cursor for what is under it (a hand on actions and rows, a text cursor in fields); over the game it stays the game's. Dragged within 8 points of the screen's edge or of the edge of another of Angelica's windows beside it, it snaps to it, and a line in the action color shows the edge it snapped to; it lets go of the edge once the pointer is 14 points away, so it neither jitters on the edge nor sticks to it. A window stays whole on the screen, as the menu does: no wider or taller than the screen, and never dragged past its edges. A collapsed window is its title bar alone, with the title, the status, and a button that expands it. Where each window is, its size when the player set one, and whether it is collapsed are kept across game starts ([layout](../formats/host-installation-v1.md#layout)). A plugin cannot draw outside its places or show Angelica's own controls.

### Panels and the layout mode

A new panel appears at its `anchor`, a point of the screen such as the bottom left, 24 points from the edges, and moves aside from panels already there. The player places panels in the layout mode, opened by **Arrange panels** in the Angelica menu's button: the game stays in view, every panel the player's plugins return is shown with a dashed outline and its name and when it is shown, and the player drags it; a panel's right-click menu chooses when it is shown (**Always**, **In combat**, **Out of combat**, as the plugin says, or **Hidden**). **Done** or `Esc` closes the layout mode. Where each panel is and the player's choice are kept across game starts. Panels are drawn under windows, menu open or closed, and over the game's own interface. When the running game map does not describe whether the player is in combat, panels shown in or out of combat are shown always.

### Dialogs

A dialog has Angelica's frame and a title bar with the question and close, and below it the plugin's parts: what is asked, its facts, and the words that answer it, the main one first. It opens over the upper part of its window, inset from the window's sides, at most 360 points wide, in front of every window, with a deeper shadow; it fades in while rising 6 points, 140 ms. The window under it is shaded and takes no input, but the player can still move, collapse, or close it, and the game and other windows go on as before. Closing the dialog is the same as not answering.

### Popups

A popup in the corner is a note like Angelica's own: the plugin's name, then its parts. A popup above the middle of the screen is bare over the game, its first text large. A popup beside a panel is on a plate next to the panel, on the side with room, and in the corner while the panel is not shown. Popups share the limits of notifications: at most 3 on the screen, the oldest leaving first.
