# Game map format v1

The game map is a directory of UTF-8 TOML files in the `angelica-gamemap` repository. `angelica-map` reads it; nothing else interprets it.

```text
map.toml                 format version
entries/<area>.toml      hand-maintained entries, one file per area
builds/<version>.toml    generated build records, one per game executable
```

`map.toml`:

```toml
format = 1
```

A reader refuses any other `format` value.

## Entry names

An entry name is lowercase dotted words, `<area>.<subject>[.<member>]`, for example `excel.store_row.hash_table` or `ui.unit_base.name`. The area is the file the entry lives in. A name is stable: renaming an entry used by published plugins keeps the old name as an alias for at least one major version of the plugin API.

## Entry kinds

Each entry is a table keyed by its name under its kind.

| Kind | Describes | Required fields |
| --- | --- | --- |
| `function` | a function | `locator`, `abi`, `thread` |
| `location` | an instruction inside a function, for a mid-function hook | `locator`, `thread` |
| `global` | a static variable | `locator`, `type` |
| `vtable` | a virtual function table | `locator`, `slots` |
| `field` | a field of a structure | `of`, `locator` or `offset`, `type` |
| `patch` | bytes to replace | `locator`, `original`, `replacement` |

Common optional fields: `doc` (one sentence: what it is, not how it was found), `checks`, `depends`, and `origin`.

## Locators

| Locator | Resolves to |
| --- | --- |
| `{ signature = "48 8B ?? …" }` | the start of the single match in the code section |
| `{ signature = "…", at = n }` | the match start plus `n` |
| `{ signature = "…", follow = "rel32", at = n }` | the target of the 32-bit relative operand at match start plus `n` (calls, jumps, RIP-relative data) |
| `{ vtable = "<entry>", slot = n }` | the function in slot `n` of a vtable entry |
| `{ in = "<function entry>", signature = "…", operand = "disp" }` | for a `field`: the displacement of the memory operand of the matched instruction inside that function |

A signature is hexadecimal bytes with `??` for any byte. A locator that matches zero or more than one address makes the entry absent.

## Function ABI and thread

```toml
[function."excel.store_row.hash_table"]
locator = { vtable = "excel.page_row_resolver.hash_table", slot = 3 }
abi = { args = ["ptr", "ptr", "ptr"], ret = "ptr" }
thread = "any"
checks = [{ signature = "48 89 5C 24 ?? 57 48 83 EC 20" }]
doc = "Stores a parsed row in a hash-table page resolver."
```

`abi` lists argument and return kinds of the Windows x64 calling convention: `i8`…`i64`, `u8`…`u64`, `f32`, `f64`, `ptr`, `bool`, `void`. `thread` is `main` or `any`.

## Checks

`checks` is a list of conditions that must hold after the locator resolves: another locator that must resolve to the same address, or `{ equals = "<entry>" }`. A failed check makes the entry absent.

## Origin

`origin` records where an entry came from when it was not found in this repository's own work, as `{ source = "<name>", commit = "<id>" }`. An entry with an origin is used like any other once it is verified; the origin keeps the provenance the source's license requires.

## Build records

Generated by `angelica map verify`, never edited by hand:

```toml
game_version = "2026.08.11.0000.0000"
exe_sha256 = "…"
map_commit = "…"

[present]
"excel.store_row.hash_table" = 0x2087C40

[absent]
"ui.example.field" = "signature matched 2 addresses"

[constant_offsets]
names = ["ui.unit_base.name"]
```

Addresses are relative to the image base. A build record applies only to the executable with its hash.
